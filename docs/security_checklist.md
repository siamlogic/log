# セキュリティ設計・チェックシート (Security Checklist & Zero Trust Architecture)

- **文書ID**: D-07

- **更新日**: 2026-10-16
- **準拠基準**: OWASP Top 10 (2021), 医療情報システムの安全管理に関するガイドライン第6.0版, AGENTS.md

## 1. 基本セキュリティ方針

本システムに入力される全てのデータ（活動内容、気分評価、自由記述メモ、支援者カルテ）は、**最高水準の要配慮個人情報（メンタルヘルス情報・絶対秘匿）**です。
本システムは**単一サーバー、単一インスタンス（Single Server / Single Instance）での運用を大前提**とし、多層防御（Defense in Depth）とZero Trust原則に基づき、外部Redis等の分散キャッシュやクラスタの障害リスクを排除した自律的な安全管理を実装しています。

## 2. セキュリティ統制項目と実装検証状況

| 統制項目 | リスクと脅威 | 対策実装内容 | 検証結果 |
| :--- | :--- | :--- | :---: |
| **A01: アクセス制御の不備 (IDOR)** | メンバーが他者の週間シートを閲覧・改ざんする | 全ての `/api/cbt/*` エンドポイントでクライアント送信の `user_id` を排除し、サーバーセッション（Cookie署名検証）から強制バインド。 | ✅ PASS (検証済) |
| **A01: 権限制御 (RBAC)** | メンバーが管理者APIにアクセスし他者情報を窃取する | `/api/admin/*` で `session.user.role === 'admin'` を検証し、非管理者には即座に 403 Forbidden を返却。 | ✅ PASS (検証済) |
| **A01: 支援者カルテの絶対秘匿** | 支援者が記録した内部メモ（`admin_memo`）がメンバー本人に漏洩する | 生のPrisma呼び出しを禁止し、`server-only` 宣言された DAL（`src/lib/dal/cbt.ts`）経由でアクセス。メンバー向けレスポンスから `admin_memo` を物理的に除外（DTOホワイトリスト変換）。 | ✅ PASS (検証済) |
| **A02: 暗号化の失敗** | 通信経路での盗聴、端末での平文漏洩 | TLS 1.3 強制、HSTSヘッダー（`max-age=63072000`）、TOTP秘密鍵の AES-256-GCM 保存時暗号化。 | ✅ PASS (検証済) |
| **A03: インジェクション** | SQLインジェクション、悪意あるクエリ | Prisma ORM による完全パラメータ化クエリ。生SQL結合は一切禁止。 | ✅ PASS (検証済) |
| **A04: 安全でない設計 (DLP)** | ExcelやCSVの端末ダウンロードによる紛失・持ち出し事故 | **データエクスポート機能を完全全廃**。全ての記録確認は認証下のWeb画面上で完結させ、ファイル持ち出しを根本排除。 | ✅ PASS (検証済) |
| **A05: セキュリティの設定不備** | Clickjacking, XSS, MIME Sniffing | HTTPセキュリティヘッダーを `next.config.mjs` で全ルートに適用。<br>- `X-Frame-Options: DENY`<br>- `X-Content-Type-Options: nosniff`<br>- `Content-Security-Policy`<br>- `Cache-Control: no-store`（全APIでブラウザキャッシュ禁止） | ✅ PASS (検証済) |
| **A07: 識別と認証の失敗 (ブルートフォース)** | パスワードや2FAコードの総当たり攻撃 | パスワードの Argon2id ハッシュ化。パスワードまたは2FAコードの連続5回失敗で15分アカウントロックアウト。IP単位およびメールアドレス単位のスライディングウィンドウ式レートリミッター。 | ✅ PASS (検証済) |
| **A07: セッション即時失効 (Revocation)** | ログアウトやPW変更後も盗取トークンでアクセスが継続する | `users.token_version` カラムによるDB検証を全セッション検証時に強制。ログアウト・PW変更時に即座にインクリメントし、旧トークンを完全無効化。 | ✅ PASS (検証済) |
| **A02: 暗号化の失敗 (暗号鍵保護)** | 通信経路での盗聴、鍵未設定時のデフォルト鍵漏洩 | TLS 1.3 強制、HSTSヘッダー（`max-age=63072000`）。TOTP秘密鍵の AES-256-GCM 暗号化。本番環境における暗号鍵未設定時の起動遮断ガード。 | ✅ PASS (検証済) |
| **A08: ソフトウェアとデータの完全性** | 2FAリプレイ攻撃、無効日付・曜日破壊 | TOTPコード検証時に `last_totp_step` を記録し同一ステップ再利用を拒否。JST基準の日付計算、週コピー時の月曜日検証、存在しない日付（2/31等）の厳格拒絶。 | ✅ PASS (検証済) |
| **A09: セキュリティログとモニタリング** | 不正アクセスの検知不能、ログへの機微情報平文出力 | `audit_logs` テーブルによる証跡管理。操作メタデータのみを記録し、患者の活動内容やカルテの平文出力（PII/PHI in Logs）を禁止。 | ✅ PASS (検証済) |
| **離席・端末放置対策** | 共用PCでの離席中に他者が画面を覗き見・操作する | クライアント側無操作タイマー（25分警告、30分自動ログアウト）の実装。 | ✅ PASS (検証済) |

## 3. 監査証跡（Audit Trail）仕様

本システムでは、以下の重要イベント発生時に `audit_logs` レコードを生成します。

```json
{
  "actorId": "admin-1",
  "targetUserId": "member-1",
  "action": "ADMIN_UPDATE_MEMO",
  "ipAddress": "192.168.1.100",
  "details": {
    "memoLength": 78,
    "timestamp": 1729074000000
  }
}
```
※活動内容本文やカルテ文章はログに含まれません。
